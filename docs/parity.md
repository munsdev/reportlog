# Parity: what the rebuild must do before `legacy/` is deleted

`legacy/` is deleted when the rebuild reaches parity. This file says what parity means, row by row.
It lists every legacy route, script, self-test, migration and screen, and gives its equivalent in
the rebuild. Each claim was checked against the code and the tests on the base branch at `81a4c77`
(D1 and C2 merged). The status docs were used only to find the reason for a drop.

- **Written:** 2026-10-19, by the parity audit session (branch `claude/parity-audit`).
- **How it was checked:**
  - The route table was printed from the running Fastify app (`app.printRoutes()`), not read from
    the source.
  - Each route path was grepped across `apps/api/test`, `apps/web/test` and `apps/web/e2e`. A
    route with no hit was traced to the module function it calls, and that function's test was
    opened.
  - Migrations, screens and the groups of `selftest.js` were audited the same way, by opening the
    test that asserts each behaviour.
- **Not done:** no suite was run for this audit. A test "asserts" something here because its body
  was read, not because it was seen passing.

**Statuses**

| Status         | Meaning                                                                                                                |
| -------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **Equivalent** | The rebuild does the same thing; the file and its test are named.                                                      |
| **Partial**    | An equivalent exists, but part of the behaviour or its test is missing. The missing part is named and counted below.   |
| **Missing**    | Nothing in the rebuild does it.                                                                                        |
| **Dropped**    | Dropped on purpose. The status doc that says so is cited. "No doc says so" means a grep of `docs/` found no such line. |
